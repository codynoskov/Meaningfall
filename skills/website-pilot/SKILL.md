# Meaningfall Website Pilot

Use this public entry route when a person wants a website Project. Read
[START.md](START.md) before installation or Project creation. It owns the
versioned release bootstrap, capability boundaries, and the compact shareable
prompt; do not copy its lifecycle procedure into chat.

Use the current repository as the Website Project when it is the selected Project
repository. If it is Meaningfall's distribution/source repository, ask for the
target repository before changing Project files. Preserve unrelated nonempty
repositories rather than treating them as Project state.

When explicitly asked, retain a human reaction to Meaningfall in the Pilot's
Project-local `Memory/NOTES.md`, with context and uncertainty. It is reviewable
evidence, not an upstream synchronization or an automatic Meaningfall change.

The pilot needs only Project and Environment. Do not create, require, look up,
migrate, or simulate an Actor, Actor Profile, Actor ID, or Actor memory.

Use Website Guidance for inquiry and research. Preserve unknowns, use DataForSEO
only when search evidence can change Product Meaning, and require acceptance of a
material Product Meaning before broad Realization. A local browser preview and
rendered verification are required before publication. Cloudflare is optional and
requires a separate explicit publication authorization.
